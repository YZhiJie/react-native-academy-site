06 · JS 侧核心：看不见的管家们 ​

前几章的主角都是"跨语言通信"这类大工程。这一章换一班人马：四位常驻 JS 世界的管家。他们平时不出镜，但你写下的每一行 RN 代码，背后都有他们在值班。

一、开机管家：InitializeCore ​

每个 App 的 JS bundle 执行的第一份"实质文件"就是它。但 0.87 里，[InitializeCore.js:L13-L37](file:///Users/yangzhijie/Desktop/practice_projects/claude-code-test/_rn-source/react-native-0.87.1/Libraries/Core/InitializeCore.js#L13-L37) 已经瘦成一具壳——注释里明说"此文件只是兼容入口，真正逻辑在 setup"。真正的活由 [src/setup-env.js:L14-L22](file:///Users/yangzhijie/Desktop/practice_projects/claude-code-test/_rn-source/react-native-0.87.1/src/setup-env.js#L14-L22) 委托给 setUpDefaultReactNativeEnvironment：

  • 装上全局 polyfill 与错误上报通道；
  • 打性能标记（TTRC 时长统计的起点）；
  • 注册核心可回调模块（BatchedBridge 的"通讯簿"）。

记住这个分层：壳 → setup-env → private/setup。官方在把"启动时必须做的事"一路下沉、逐件瘦身——这正是 0.87 秒开优化的主线剧情。

二、触控管家：Pressability ​

你写的 onPress 其实是台词，真正演出的是 [Pressability.js](file:///Users/yangzhijie/Desktop/practice_projects/claude-code-test/_rn-source/react-native-0.87.1/Libraries/Pressability/Pressability.js)。它内部是一台显式状态机：[L663-L698](file:///Users/yangzhijie/Desktop/practice_projects/claude-code-test/_rn-source/react-native-0.87.1/Libraries/Pressability/Pressability.js#L663-L698) 的 Transitions 表写清了每个事件在什么状态下触发什么迁移。

而 [L447-L549](file:///Users/yangzhijie/Desktop/practice_projects/claude-code-test/_rn-source/react-native-0.87.1/Libraries/Pressability/Pressability.js#L447-L549) 是落点分流：responderGrant（抢到触摸权）→ responderRelease（松手）→ onClick → 最终触发你的 onPress。

三、动画管家：Animated ​

Animated 的第一决策点在 [Animation.js:L54-L58](file:///Users/yangzhijie/Desktop/practice_projects/claude-code-test/_rn-source/react-native-0.87.1/Libraries/Animated/src/nodes/Animation.js#L54-L58)：useNativeDriver 为 true 时，整段动画（时长、曲线、循环）被一次性打包，经 startAnimatingNode（[L126-L180](file:///Users/yangzhijie/Desktop/practice_projects/claude-code-test/_rn-source/react-native-0.87.1/Libraries/Animated/src/nodes/Animation.js#L126-L180)）送进原生，由原生时钟逐帧驱动——JS 线程卡死动画也不卡。

指令的运输还有个省流设计：[NativeAnimatedHelper.js:L89-L164](file:///Users/yangzhijie/Desktop/practice_projects/claude-code-test/_rn-source/react-native-0.87.1/Libraries/Animated/src/NativeAnimatedHelper.js#L89-L164) 的 singleOpQueue 把零散操作攒成批量单条指令再发车。

旧时代的属性驱动（setValue 逐次跨桥）每帧一次往返；新架构下连"发车"都批量化了。组件篇的 Bouncy Checkbox、Skeleton 都建在这套地基上。

四、列表管家：VirtualizedList ​

FlatList 的全部滚动魔法都来自 VirtualizedList。它在 0.87 里的身份是个"二传手"：[VirtualizedList.js:L13-L20](file:///Users/yangzhijie/Desktop/practice_projects/claude-code-test/_rn-source/react-native-0.87.1/Libraries/Lists/VirtualizedList.js#L13-L20) 只是把实现从 @react-native/virtualized-lists 包再导出——官方把核心算法拆成独立 npm 包，方便单独发版修 bug。

核心思想一句话：窗口化——只渲染视口附近几十条，滚近补货、滚远回收。而 [FlatList.js:L83-L95](file:///Users/yangzhijie/Desktop/practice_projects/claude-code-test/_rn-source/react-native-0.87.1/Libraries/Lists/FlatList.js#L83-L95) 的 getItemLayout 能让它跳过逐项测量、直飞目标行——这就是"跳到指定条目"瞬间完成的原因。

五、FAQ ​

Q1：InitializeCore 里的代码我能改吗？ 不要改源码——它有 setUpReactNativeEnvironment 之类的官方注入点；业务初始化请放入口文件 index.js 里 AppRegistry.registerComponent 之前。

Q2：为什么我的 onPress 有时会"失灵"？ 先查状态机两件事：是否在 release 前手指滑出了按压区；是否父级用可滚动手势抢走了 responder。状态机是严格按 Transitions 表走的，不是玄学。

Q3：useNativeDriver 能驱动所有属性吗？ 不能——只支持非布局属性（transform、opacity 等）。布局属性（width/height）走原生驱动需要布局系统参与，得用 Reanimated 的 layout 动画或手势方案。
