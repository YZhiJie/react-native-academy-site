00 · 导读：出发之前 ​

本系列所有结论都来自 react-native@0.87.1 官方 npm 包的真实源码（31MB，含 JS / C++ / Objective-C / Kotlin 全量实现），每一条都标了文件路径与行号。漫画负责让你看懂，源码负责让你信服。

一、React Native 0.87.1 是个什么版本？ ​

先看它的"身份证"——[package.json](file:///Users/yangzhijie/Desktop/practice_projects/claude-code-test/_rn-source/react-native-0.87.1/package.json)：

项目值为什么重要
React（peer 依赖）^19.2.3渲染核心是 React 19，Concurrent 特性全量可用
Node 要求^22.13.0 || ^24.3.0 || >= 26.0.0老旧 Node 装不上 0.87，教程第 01 章会讲
Metro0.87.x打包器与 RN 同版本节奏
@react-native/codegen0.87.1（固定版本）新架构的代码生成器，随 RN 锁版本
默认 JS 引擎HermesAOT 编译字节码，启动快、内存省

三个关键词，构成 0.87 的时代底色：

  1. 新架构默认化（New Architecture）：Fabric 渲染器 + TurboModules + Codegen，从 0.76 起就是默认项，0.87 已是唯一推荐路径，旧 Bridge 只留了兼容层。
  2. bridgeless 默认化：RCTBridge（iOS）的构造 API 已在源码中标记废弃——[React/Base/RCTBridge.h](file:///Users/yangzhijie/Desktop/practice_projects/claude-code-test/_rn-source/react-native-0.87.1/React/Base/RCTBridge.h#L96-L124) 注释直言 "随 legacy architecture 移除"。
  3. Apple 侧大重组：出现了独立目录 ReactApple/，并且迎来一位新客人——RCTSwiftUI（用 SwiftUI 实现的滤镜/效果容器，第 08 章细讲）。

打开后是一张这样的地图：

目录语言角色（漫画比喻）
index.jsJS大门：所有公开 API 从这里导出（而且是懒加载！）
Libraries/JS前台服务区：40+ 个子目录，你 import 的组件都住这里
src/private/JS员工通道：不公开的内部实现（如启动环境搭建）
ReactCommon/C++地下枢纽：jsi、cxxreact、react/renderer、yoga……双端共享
React/ObjCiOS 老城区：CoreModules、Views、Fabric 挂载
ReactApple/ObjC/SwiftiOS 新城区：0.87 新设，SwiftUI 实验田
ReactAndroid/Kotlin/Java/C++Android 工厂：ReactHost、Fabric 组件工厂、JNI
sdks/、scripts/、gradle/杂后勤仓库：hermes 引擎、构建脚本

一个有趣的细节：index.js 导出的每个 API 都是 getter 惰性求值——

js
// react-native-0.87.1/index.js:L32-L40（节选）
module.exports = {
  // #region Components
  get ActivityIndicator() {
    return require('./Libraries/Components/ActivityIndicator/ActivityIndicator')
      .default;
  },
  get Button() {
    return require('./Libraries/Components/Button').default;
  },

四、FAQ ​

Q1：为什么不直接读 GitHub 仓库？ npm 包就是你 npm install react-native 后真实编译进 App 的源码（iOS 的 podspec、Android 的 prefab 都指向 node_modules 里的这些文件）。读它 = 读你 App 真正在跑的代码。GitHub 上多出来的主要是 CI、网站和测试基建。

Q2：0.87 还能写老架构代码吗？ 能跑（兼容层还在），但官方已经把 RCTBridge 构造 API 标记 deprecated，第三方库生态全面转向新架构。教程全程按新架构 + bridgeless 讲。

Q3：我没有 Mac，iOS 章节能读吗？ 能。iOS 章是"理解型"内容，帮助你明白双端差异；动手篇（教程）对 Android / macOS / Windows 三个平台都给了完整步骤。
