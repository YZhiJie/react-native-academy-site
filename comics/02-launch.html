02 · 启动大戏：从点开图标到第一帧 ​

启动是理解一个框架最快的切入口。0.87 的启动已全面转向 bridgeless + 新架构，本章按真实源码把双端时序走一遍。

一、三段式总纲 ​

text
第一段（原生侧）：进程起来 → 建好"C++ 运行时"的壳 → 准备 JS 引擎
第二段（JS 侧）  ：加载 bundle → 搭环境 → 你的组件在 AppRegistry 登记造册
第三段（合流）    ：原生回调 runApplication → React 渲染 → Fabric mount → 首帧

二、iOS 泳道：从 main() 到 Hermes ​

第 1 步：AppDelegate 接管。 模板生成的 AppDelegate 继承自 RN 提供的 RCTAppDelegate，在 didFinishLaunching 里把"主组件名"交给 RN，由 RCTRootViewFactory 负责创建根视图（bridgeless 模式的标志性入口）。

第 2 步：bundle 地址从哪来。 [React/Base/RCTBundleManager.m](file:///Users/yangzhijie/Desktop/practice_projects/claude-code-test/_rn-source/react-native-0.87.1/React/Base/RCTBundleManager.m#L81-L99) 决定加载 Metro 开发服务器还是打进包里的本地 bundle；L103-L167 还专门为 bridgeless 模式增加了 bundle URL 的 getter/setter 回调——调试热更新就靠它换地址。

第 3 步：Hermes 引擎就位。 iOS 侧的接线在 [scripts/cocoapods/jsengine.rb](file:///Users/yangzhijie/Desktop/practice_projects/claude-code-test/_rn-source/react-native-0.87.1/scripts/cocoapods/jsengine.rb#L8-L20)：setup_hermes! 把 hermes-engine 与 React-hermes 两个 pod 装进依赖图。

一个小结论：RCTBridge 的构造 API 已被标记 deprecated（[React/Base/RCTBridge.h:L96-L124](file:///Users/yangzhijie/Desktop/practice_projects/claude-code-test/_rn-source/react-native-0.87.1/React/Base/RCTBridge.h#L96-L124)，注释写明"随 legacy architecture 移除"）。0.87 的 iOS 启动不再"过桥"。

internal fun startSurface(surface: ReactSurfaceImpl): TaskInterface<Void> {
  // 先挂上 surface，再等 ReactInstance 就绪后调
  // reactInstance.startSurface(surface) 开始渲染
  attachSurface(surface)

4.3 开演：原生回调 runApplication ​

原生侧就绪后调用（这是我逐行验证过的完整函数）：

js
// Libraries/ReactNative/AppRegistryImpl.js:L197-L216（节选）
export function runApplication(appKey, appParameters, displayMode) {
  if (appKey !== 'LogBox') {
    console.log(`Running "${appKey}"...`);      // 控制台那行 Running 就是这来的
  }
  invariant(
    runnables[appKey],
    `"${appKey}" has not been registered. This can happen if:\n` +
      '* Metro (the local dev server) is run from the wrong folder. ...',
  );
  runnables[appKey](appParameters, coerceDisplayMode(displayMode));
}

五、FAQ ​

Q1：为什么开发时要跑 Metro，发布时不用？ 开发时 RCTBundleManager 指向 http://localhost:8081（随时换 bundle 热刷）；发布时 bundle 作为资源打进 App，Hermes 直接执行 AOT 字节码。

Q2：Running "xxx" 后卡住不动，查哪里？ 按链路查：bundle 是否编译失败（终端报错）→ 是否有模块在 import 时抛异常（registerComponent 没执行）→ native 侧 Hermes 是否加载成功。

Q3：启动优化我能做什么？ 源码已经替你做了三件事：API 懒加载（index.js getter）、模块延迟注册（ViewConfig 回调）、Android 后台预初始化（ReactHostImpl.start）。你能做的是：减少首屏 import 的重模块、首屏列表用 getItemLayout 跳过测量（第 06 章）。
