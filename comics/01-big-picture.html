01 · 三层世界：JS、C++、原生的大地图 ​

一、为什么非要三层？ ​

你写的 JS 代码只能"描述"界面，而屏幕上的像素归操作系统管。中间必然需要一个翻译层。React Native 0.87 的答案是：

text
你的代码（JS）        →  "我想要一个蓝色按钮"        （愿望）
C++ 枢纽              →  "收到，布局算好了，指令在此" （翻译 + 调度）
原生（iOS/Android）   →  "按钮已上屏"               （施工）
1
2
3

三层缺一不可：

  • 只有 JS？ 调不了摄像头、画不了原生模糊，也碰不到屏幕像素。
  • 只有原生？ 失去"写一次 JS 双端跑"的开发效率。
  • 中间为什么是 C++？ 因为 iOS 和 Android 是两个王国，只有 C++ 这门"中立语言"两边都认。一份 ReactCommon/，双端共享，这是 RN 长期演进的根基。

export function createReactNativeComponentClass(
  name: string,
  callback: GetViewConfig,
): string {
  invariant(
    !ReactNativeViewConfigRegistry.registeredNames.has(name),
    'Tried to register two views with the same name %s',
    name,
  );
  ReactNativeViewConfigRegistry.register(name, callback);
  return name;
}

2.3 原生双大陆 ​

iOS：老城 + 新城。React/ 是 ObjC 老城区（CoreModules/、Views/、Fabric/Mounting/ComponentViews/）；ReactApple/ 是 0.87 新设的新城区，官方 README 只有一句话——Apple 原生侧新库目录，主导语言 Objective-C——里面最惹眼的是 RCTSwiftUI/（Swift 写的滤镜容器）与 RCTSwiftUIWrapper/（ObjC 包装层）。第 08 章专程探访。

Android：一座工厂。ReactAndroid/src/main/java/com/facebook/react/ 下，runtime/ReactHostImpl.kt 是新架构的总调度，fabric/ComponentFactory.kt 是组件工厂大门，JNI 层在 src/main/jni/。第 07 章进厂参观。

三、一条消息如何跨界（先立个纲） ​

从本章起，请记住 0.87 的跨界总纲：

  1. JS ↔ C++：走 JSI，同步、直接、无序列化（第 03 章）。
  2. C++ ↔ 原生视图：走 Fabric mount 指令，由 C++ 把"影子树 diff"翻译成 Create/Insert/Update 指令（第 05 章）。
  3. JS ↔ 平台能力（相机、存储…）：走 TurboModule，由 Codegen 生成的类型化桩代码护航（第 04 章）。

四、FAQ ​

Q1：Libraries/ 和 src/private/ 什么区别？Libraries/ 是公开 API 的家（你能 import 的都在这）；src/private/ 是内部实现，比如启动环境搭建 src/setup-env.js，公开的 InitializeCore 现在只是它的转发壳（第 02 章展开）。

Q2：Yoga 为什么算 C++ 层而不是原生层？ 因为布局计算与"哪个平台"无关——Android 和 iOS 的 View 都拿同一套 Yoga 结果去摆放自己。它是纯粹的计算服务。

Q3：React 19 和这三层是什么关系？ React 19 负责"从 state 算出该渲染什么"（reconciler），产物交给 ReactFabric；三层地图里的"JS 世界"其实 = 你的代码 + React 19 + Libraries。
