教程 10 · WebView 离线：把内嵌 H5 做成"断网可用、版本可回滚" ​

目标：让 App 内嵌的 H5 页面在网络不可用时仍能打开、能操作，并且能安全地升级与回滚。 版本锚点：React Native 0.87.1（新架构 bridgeless + Hermes）；react-native-webview 以当前稳定版为准（写作时 npm latest 为 14.0.1，安装前请复核）。 前置：09 · 离线能力——本章的 Native 缓存、outbox 与网络状态会直接复用。

WebView 离线的难点不在"把 HTML 下载下来"，而在三件事：

  1. 加载路径可控：页面到底是从 https:// 来的，还是从本地包来的？
  2. 版本可回滚：新包白屏时，能不能在 3 秒内退回上一版？
  3. 能力边界清楚：哪些事 WebView 根本做不到，必须 Native 兜底？

本章按这三条线展开，并在最后给出一张"能力边界总表"。

一、接入与两端差异 ​

依赖兼容性（以实际安装版本为准）：

  • react-native-webview@14.0.1 的 package.json 带 codegenConfig（type: "all"），官方提供 Fabric 组件与 TurboModule，0.87.1 新架构可用。
  • react-native-zip-archive@9.5.3 同样带 codegenConfig（type: "modules"），peerDependencies 要求 RN ≥ 0.70。
  • react-native-blob-util@0.25.1 自带 codegenConfig（type: "modules"）；官方 README 明确写了 0.17.0 起支持新架构，0.22.0 起要求 RN ≥ 0.76，0.87.1 满足。
  • 本章不再使用 react-native-fs：它 2022 年停更、没有 codegenConfig，在 bridgeless 下只能靠 interop layer。文件下载、校验和、移动与目录操作全部由 blob-util 承担；解压仍交给 react-native-zip-archive。

实测（2026-11，RN 0.87.1 / iPhone 17 iOS 26.5 模拟器）：react-native-webview@14.0.1 与 react-native-blob-util@0.25.1 安装、pod install 与构建均通过。config().fetch() 在本机回环服务上 10MB 用 6ms、20MB 用 8ms，落盘后 SHA-256 与服务端一致（回环数字不代表真实网络）。react-native-zip-archive@9.5.3 的 podspec 依赖 SSZipArchive，本环境无法从 CocoaPods CDN / GitHub 拉取，安装未完成，本章解压耗时与失败形态仍未实测。

最小可用容器：

tsx
// src/h5/H5Screen.tsx
import React from 'react';
import { Platform } from 'react-native';
import { WebView } from 'react-native-webview';
import ReactNativeBlobUtil from 'react-native-blob-util';

/**
 * 本地包的根路径：
 * - Android：打进 assets 的 h5/ 目录，固定用 file:///android_asset/
 * - iOS：随 Bundle 分发，用主 Bundle 路径
 */
const LOCAL_BASE = Platform.select({
  ios: `file://${ReactNativeBlobUtil.fs.dirs.MainBundleDir}/h5/`,
  android: 'file:///android_asset/h5/',
  default: '',
});

export function H5Screen() {
  return (
    <WebView
      source={{ uri: `${LOCAL_BASE}index.html` }}
      // 只允许本地包与业务域名，其余一律拦截（含 http:、intent: 等）
      originWhitelist={['file://*', 'https://app.example.com']}
      // Android 读取 assets 内文件所需；远程页面不要开这三个开关
      allowFileAccess
      allowFileAccessFromFileURLs
      allowUniversalAccessFromFileURLs
      // iOS：只允许 WebView 读取这个目录，避免任意 file:// 越权
      allowingReadAccessToURL={LOCAL_BASE}
      javaScriptEnabled
    />
  );
}

1.1 iOS WKWebView vs Android WebView ​

维度iOS（WKWebView）Android（WebView）
内核系统 WebKit，版本随 iOS系统 Chromium，版本随厂商/系统，可能很旧
本地文件必须配 allowingReadAccessToURL，且 originWhitelist 要包含 file://需 allowFileAccess 等开关，路径 file:///android_asset/
请求拦截原生 WKURLSchemeHandler原生 shouldInterceptRequest
Service Worker不支持（WKWebView 未实现）支持，但要求安全上下文（https / localhost）
缓存清理需操作 WKWebsiteDataStoreclearCache(true) 可用
调试Safari 开发菜单Chrome chrome://inspect
CookiesharedCookiesEnabled 行为差异大thirdPartyCookiesEnabled 需显式处理

结论：跨端行为不要假设一致。本地加载、缓存、Cookie 这三块必须双端各测一遍。

实测（iPhone 17 / iOS 26.5，react-native-webview 14.0.1）：默认 originWhitelist 只放行 http/https，file:// 页面不触发任何回调（onShouldStartLoadWithRequest/onLoadStart 都不来），6 秒内始终白屏；加上 originWhitelist={['*']} 与 allowingReadAccessToURL 后，file:// 首屏 shouldStart → loadStart → loadEnd 约 585ms 完成，页内跳转也会再次触发 shouldStart（实测 sub.html 在 853ms 触发）；在 onShouldStartLoadWithRequest 返回 false 能阻止跳转（只留下 shouldStart-blocked，无后续 loadStart）。Android 侧未实测。

2.3 运行期：整页本地化 vs 资源拦截 ​

这是最容易含糊的地方，必须说清能力边界：

需求纯 JS / react-native-webview 能做吗正确做法
整页从本地包加载✅ 可以source 传入 { uri: LOCAL_BASE + 'index.html' }
页面内相对资源走本地✅ 可以构建期 base: './'，资源随包分发
远程页面里的资源改走本地❌ 不能onShouldStartLoadWithRequest 只能放行/拦截，不能改写响应
按 URL 规则把请求映射到本地文件❌ 不能必须 Native 拦截：iOS WKURLSchemeHandler，Android shouldInterceptRequest
替换 Cookie / 注入请求头❌ 不可靠Native 侧统一下发，H5 不自行维护

onShouldStartLoadWithRequest 的正确用途是白名单，不是重定向：

ts
// src/h5/allowed.ts
const LOCAL_PREFIX = 'file:///android_asset/h5/';
const ALLOWED_HOSTS = new Set(['app.example.com']);

export function isAllowed(url: string): boolean {
  // 只放行打包目录下的 file://
  if (url.startsWith(LOCAL_PREFIX) || url.startsWith('file://')) {
    return url.includes('/h5/'); // 防止读到沙盒其他文件
  }

  try {
    const parsed = new URL(url);
    // 只允许 https 且域名在白名单内；http 明文一律拒绝
    return parsed.protocol === 'https:' && ALLOWED_HOSTS.has(parsed.host);
  } catch {
    return false; // intent://、market:// 等一律拒绝，防止外部 App 唤起
  }
}

三、Service Worker / PWA 在 WebView 里的真实边界 ​

很多方案文档会写"用 Service Worker 做离线"，但在 App 内嵌场景里这句话只对一半：

能力iOS WKWebViewAndroid WebView结论
注册 Service Worker不支持支持iOS 上整条方案不可用
SW 生效前提——必须是安全上下文（https / localhost）file:// 包内页面无法注册 SW
PWA manifest / 安装不适用不适用WebView 里没有"添加到主屏幕"
localStorage / IndexedDB支持支持可用，但可能被系统清理，不能当唯一数据源
AppCache已移除已移除不要再用

具体支持情况会随 iOS / Android 系统版本与 WebView 内核版本变化，上线前请在目标机型实测，不要只按表格下结论。

所以：

  • SW/PWA 只能作为"在线 https 页面"的补充（例如远程活动页）；
  • 不能作为 App 内嵌离线的主方案；
  • 主方案只能是：本地离线包 + Native 持久缓存 + JSBridge。

4.2 灰度 + 下载 + 校验 ​

ts
// src/h5/offline.ts
import ReactNativeBlobUtil from 'react-native-blob-util';
import { ROOT, stagingZip } from './paths';
import type { OfflineManifest } from './offlineTypes';

const fs = ReactNativeBlobUtil.fs;

async function ensureDir(path: string): Promise<void> {
  if (await fs.exists(path)) return;
  // blob-util 的 mkdir 不保证自动补全父目录：递归创建，避免首次下发时 ROOT 不存在
  const parent = path.slice(0, path.lastIndexOf('/'));
  if (parent && parent !== path) await ensureDir(parent);
  await fs.mkdir(path);
}

/** 稳定哈希：同一设备每次都落在同一灰度桶里，避免"刷新一次换一个桶" */
function inRollout(deviceId: string, rollout: number): boolean {
  let hash = 5381;
  for (let i = 0; i < deviceId.length; i += 1) {
    hash = ((hash << 5) + hash + deviceId.charCodeAt(i)) >>> 0;
  }
  return hash % 100 < rollout;
}

export async function downloadAndVerify(
  manifest: OfflineManifest,
  deviceId: string,
): Promise<string> {
  if (!inRollout(deviceId, manifest.rollout)) {
    throw new Error('not-in-rollout');
  }

  await ensureDir(`${ROOT}/staging`);
  const zipPath = stagingZip(manifest.version);

  // 先下到 staging：绝不影响正在使用的版本。
  // path + overwrite 表示"直接落到指定文件"，不走 fileCache。
  const response = await ReactNativeBlobUtil.config({
    path: zipPath,
    overwrite: true,
    timeout: 30_000,
  }).fetch('GET', manifest.url, { Accept: 'application/zip' });

  const status = response.info().status;
  if (status !== 200) {
    if (await fs.exists(zipPath)) await fs.unlink(zipPath);
    throw new Error(`download-failed:${status}`);
  }

  // fs.hash 由原生计算流式摘要，不需要把整个 zip 读进 JS 内存
  const actual = (await fs.hash(zipPath, 'sha256')).toLowerCase();
  if (actual !== manifest.sha256.toLowerCase()) {
    // 校验失败：宁可不用，也不加载可能损坏/被篡改的包
    await fs.unlink(zipPath);
    throw new Error('checksum-mismatch');
  }

  return zipPath;
}

4.4 安装与原子切换 ​

ts
// src/h5/install.ts
import ReactNativeBlobUtil from 'react-native-blob-util';
import { unzip } from 'react-native-zip-archive';
import { CURRENT_FILE, ROOT, packageDir } from './paths';
import type { CurrentState, OfflineManifest } from './offlineTypes';

const fs = ReactNativeBlobUtil.fs;

async function ensureDir(path: string): Promise<void> {
  if (await fs.exists(path)) return;
  // 同上：先补父目录，再创建自己
  const parent = path.slice(0, path.lastIndexOf('/'));
  if (parent && parent !== path) await ensureDir(parent);
  await fs.mkdir(path);
}

async function readCurrent(): Promise<CurrentState | null> {
  try {
    if (!(await fs.exists(CURRENT_FILE))) return null;
    return JSON.parse(await fs.readFile(CURRENT_FILE, 'utf8')) as CurrentState;
  } catch {
    return null; // 指针文件损坏 → 视为没有当前版本，触发回滚
  }
}

export async function installPackage(
  manifest: OfflineManifest,
  zipPath: string,
): Promise<void> {
  const target = packageDir(manifest.version);
  await ensureDir(`${ROOT}/packages`);

  // 先解压到独立的版本目录：失败也只影响这个新目录
  if (await fs.exists(target)) await fs.unlink(target);
  await unzip(zipPath, target);
  await fs.unlink(zipPath);

  const current = await readCurrent();
  const next: CurrentState = {
    version: manifest.version,
    previousVersion: current?.version,
  };

  // 切换指针：先写临时文件，再 mv 成正式指针
  const tmp = `${CURRENT_FILE}.tmp`;
  await fs.writeFile(tmp, JSON.stringify(next), 'utf8');
  if (await fs.exists(CURRENT_FILE)) await fs.unlink(CURRENT_FILE);
  const moved = await fs.mv(tmp, CURRENT_FILE);
  if (!moved) throw new Error('pointer-switch-failed');
}

实测（iPhone 17 / iOS 26.5，react-native-blob-util 0.25.1）：fs.mv(src, 已存在目标) 抛错且不覆盖——目标内容保持原值、源文件仍在（错误文案为 "couldn't be moved ... an item with the same name already exists"）；mv 到不存在的目标则成功且源被移除。所以指针切换必须先 unlink 再 mv，不能指望 mv 覆盖。fs.hash('sha256') 返回小写 hex（与 sha256sum 输出一致）。

文件操作选型：react-native-blob-util 长期活跃，下载、文件系统、哈希都在一个库里；react-native-fs 2022 年停更且无 codegenConfig，只适合存量项目。

原子性的现实约束：POSIX 的 rename() 是原子的，但 fs.mv 在"目标已存在"时的行为随平台/版本而变。上面的"先 unlink 再 mv"存在极短的指针缺失窗口；生产环境建议用原生 rename(2) 封装，或改成"双指针 + 校验和"方案（current-a.json / current-b.json，读取时取有效且版本更高的那个）。

4.5 回滚与清理 ​

ts
// src/h5/rollback.ts
import ReactNativeBlobUtil from 'react-native-blob-util';
import { CURRENT_FILE, ROOT, packageDir } from './paths';
import type { CurrentState } from './offlineTypes';

const fs = ReactNativeBlobUtil.fs;

async function readCurrent(): Promise<CurrentState | null> {
  try {
    if (!(await fs.exists(CURRENT_FILE))) return null;
    return JSON.parse(await fs.readFile(CURRENT_FILE, 'utf8')) as CurrentState;
  } catch {
    return null;
  }
}

export async function rollback(): Promise<string | null> {
  const current = await readCurrent();
  if (!current?.previousVersion) return null;

  const prevDir = packageDir(current.previousVersion);
  if (!(await fs.exists(prevDir))) return null; // 旧版本已被清理，无法回滚

  // 回滚同样是"写指针"，不动包目录：可回滚多次
  const next: CurrentState = { version: current.previousVersion };
  await fs.writeFile(CURRENT_FILE, JSON.stringify(next), 'utf8');
  return current.previousVersion;
}

/** 只保留当前版本 + 上一版本，其余清理，避免沙盒无限膨胀 */
export async function cleanupOldPackages(): Promise<void> {
  const current = await readCurrent();
  const keep = new Set(
    [current?.version, current?.previousVersion].filter((v): v is string => Boolean(v)),
  );

  const packagesDir = `${ROOT}/packages`;
  if (!(await fs.exists(packagesDir))) return;

  // 实测：iOS 上 fs.ls 只返回文件名（不含目录前缀，子目录同样只给名字）；Android 未实测，仍统一补绝对路径
  const entries = await fs.ls(packagesDir);
  for (const entry of entries) {
    const full = entry.includes('/') ? entry : `${packagesDir}/${entry}`;
    const name = full.slice(full.lastIndexOf('/') + 1);
    if ((await fs.isDir(full)) && !keep.has(name)) {
      await fs.unlink(full);
    }
  }
}

4.6 完整流程串起来 ​

ts
// src/h5/update.ts
import { cleanupOldPackages } from './rollback';
import { downloadAndVerify } from './offline';
import { installPackage } from './install';
import { verifySignature } from './signature';
import type { OfflineManifest } from './offlineTypes';

export async function checkAndUpdate(
  manifestUrl: string,
  deviceId: string,
): Promise<'updated' | 'up-to-date' | 'skipped'> {
  // ① 拉 manifest（必须 https + 短超时）
  const res = await fetch(manifestUrl, { headers: { 'Cache-Control': 'no-cache' } });
  if (!res.ok) throw new Error(`manifest-failed:${res.status}`);
  const manifest = (await res.json()) as OfflineManifest;

  // ② 签名校验（Native）
  const payload = JSON.stringify({
    version: manifest.version,
    url: manifest.url,
    sha256: manifest.sha256,
    size: manifest.size,
  });
  if (!(await verifySignature(payload, manifest.signature))) {
    throw new Error('signature-invalid');
  }

  // ③ 下载 + 校验和
  const zipPath = await downloadAndVerify(manifest, deviceId);

  // ④ 解压到新目录 + 原子切换指针
  await installPackage(manifest, zipPath);

  // ⑤ 只保留两代，控制磁盘占用
  await cleanupOldPackages();

  return 'updated';
}

5.2 H5 侧：带超时的 Promise 封装 ​

html
<script>
  // H5 侧：所有调用都带 id，Native 原样回传，避免并发响应错配
  var pending = {};

  function callNative(method, params) {
    return new Promise(function (resolve, reject) {
      var id = String(Date.now()) + Math.random().toString(16).slice(2);
      pending[id] = { resolve: resolve, reject: reject };

      window.ReactNativeWebView.postMessage(
        JSON.stringify({ id: id, method: method, params: params })
      );

      // 桥必须超时：Native 线程卡住时不能让 H5 永远 pending
      setTimeout(function () {
        if (pending[id]) {
          delete pending[id];
          reject(new Error('bridge timeout'));
        }
      }, 3000);
    });
  }

  // Native 通过 injectJavaScript 回调这个全局函数
  window.__bridgeResolve = function (id, ok, payload) {
    var p = pending[id];
    if (!p) return;
    delete pending[id];
    ok ? p.resolve(payload) : p.reject(new Error(String(payload)));
  };
</script>

5.3 Native 侧：把桥接到 09 章的存储 ​

tsx
// src/h5/useBridge.ts
import { useCallback } from 'react';
import type { WebView, WebViewMessageEvent } from 'react-native-webview';
import type { RefObject } from 'react';
import { kv } from '../storage';
import { enqueueNote } from '../sync/outbox';
import { drainOutbox } from '../sync/drain';
import { sendOutbox } from '../sync/send';
import type { BridgeRequest, BridgeResponse } from './bridgeTypes';

// react-native-webview 14 的类组件泛型默认是 undefined，直接写 WebView 会得到 never；
// 用 WebView<{}> 显式声明"没有额外 props"，ref 类型才可用
export function useBridge(webviewRef: RefObject<WebView<{}> | null>) {
  const respond = useCallback(
    (payload: BridgeResponse) => {
      // 注意：这里用 JSON.stringify 拼 JS，生产建议把 payload 再包一层 encodeURIComponent
      const code = `window.__bridgeResolve(
        ${JSON.stringify(payload.id)},
        ${payload.ok},
        ${JSON.stringify(payload.error ?? payload.result ?? null)}
      );`;
      webviewRef.current?.injectJavaScript(code);
    },
    [webviewRef],
  );

  return useCallback(
    async (event: WebViewMessageEvent) => {
      let req: BridgeRequest;
      try {
        req = JSON.parse(event.nativeEvent.data) as BridgeRequest;
      } catch {
        return; // 非协议消息（例如心跳文本）忽略
      }

      try {
        switch (req.method) {
          case 'cache.get':
            respond({
              id: req.id,
              ok: true,
              result: await kv.get((req.params as { key: string }).key),
            });
            break;

          case 'cache.set': {
            const { key, value } = req.params as { key: string; value: unknown };
            await kv.set(key, value);
            respond({ id: req.id, ok: true, result: true });
            break;
          }

          case 'queue.enqueue':
            // 复用 09 章的离线写入：H5 的表单提交也进同一条 outbox
            await enqueueNote(req.params as Parameters<typeof enqueueNote>[0]);
            respond({ id: req.id, ok: true, result: true });
            break;

          case 'queue.flush':
            respond({ id: req.id, ok: true, result: await drainOutbox(sendOutbox) });
            break;

          default:
            respond({ id: req.id, ok: false, error: 'unknown-method' });
        }
      } catch (error) {
        respond({ id: req.id, ok: false, error: String(error) });
      }
    },
    [respond],
  );
}

要点说明
超时每个请求 3 秒；H5 不能无限等待

六、白屏兜底页与超时治理 ​

白屏有三种来源，处理方式不同：

来源表现处理
网络慢/无网onError 或长时间无 onLoadEnd超时 → 切本地离线页
HTTP 错误onHttpError（4xx/5xx）直接切兜底页，允许重试
JS 运行时异常HTTP 200、页面已加载但白屏H5 注入 window.onerror 上报 + Native 超时兜底

实测（iPhone 17 / iOS 26.5，react-native-webview 14.0.1）：连接被拒（https://127.0.0.1:1、http://127.0.0.1:9）时，只收到 shouldStart → loadStart → loadEnd，且 loadStart 到 loadEnd 仅 4ms，onError 与 onHttpError 都没有触发。也就是说连接失败会以"加载完成"的形态结束，仅靠 onLoadEnd 必然误判为成功。

tsx
// src/h5/HybridWebView.tsx
import React, { useCallback, useEffect, useRef, useState } from 'react';
import {
  ActivityIndicator,
  Button,
  StyleSheet,
  Text,
  View,
} from 'react-native';
import { WebView } from 'react-native-webview';

type Phase = 'loading' | 'ready' | 'error';

export function HybridWebView({
  uri,
  onFallback,
}: {
  uri: string;
  onFallback?: () => void;
}) {
  // 同 useBridge：显式 <{}> 绕开 v14 类型默认值导致的 never
  const ref = useRef<WebView<{}>>(null);
  const [phase, setPhase] = useState<Phase>('loading');
  const timer = useRef<ReturnType<typeof setTimeout> | null>(null);
  // 记录"本次加载是否已经失败"：onLoadEnd 在错误时也会触发，不能直接判 ready
  const failed = useRef(false);

  const clearTimer = useCallback(() => {
    if (timer.current) {
      clearTimeout(timer.current);
      timer.current = null;
    }
  }, []);

  useEffect(() => {
    timer.current = setTimeout(() => {
      // 8 秒还没 ready：主动停止加载，避免用户一直盯白屏
      ref.current?.stopLoading();
      setPhase('error');
      onFallback?.();
    }, 8_000);

    return clearTimer;
  }, [clearTimer, onFallback]);

  const retry = useCallback(() => {
    failed.current = false;
    setPhase('loading');
  }, []);

  return (
    <View style={styles.root}>
      {phase !== 'error' && (
        <WebView
          ref={ref}
          source={{ uri }}
          onLoadStart={() => {
            failed.current = false;
            setPhase('loading');
          }}
          onLoadEnd={() => {
            clearTimer();
            if (!failed.current) setPhase('ready');
          }}
          onError={() => {
            failed.current = true;
            clearTimer();
            setPhase('error');
          }}
          onHttpError={() => {
            failed.current = true;
            clearTimer();
            setPhase('error');
          }}
          onMessage={event => {
            // H5 首屏挂载后主动报到：比 onLoadEnd 更接近"真的渲染完成"
            if (event.nativeEvent.data === 'ready') {
              clearTimer();
              setPhase('ready');
            }
          }}
          // H5 侧注入：把运行时异常也变成可观测事件
          injectedJavaScript={`
            window.onerror = function (msg) {
              window.ReactNativeWebView.postMessage('js-error:' + msg);
            };
            true;
          `}
        />
      )}

      {phase === 'loading' && (
        <ActivityIndicator style={StyleSheet.absoluteFill} size="large" />
      )}

      {phase === 'error' && (
        <View style={styles.fallback}>
          <Text style={styles.title}>页面暂时无法加载</Text>
          <Text style={styles.desc}>已切换到离线兜底页，你可以稍后重试</Text>
          <Button title="重试" onPress={retry} />
        </View>
      )}
    </View>
  );
}

const styles = StyleSheet.create({
  root: { flex: 1 },
  fallback: {
    // 0.87 的类型里没有 absoluteFillObject，直接写四边定位
    position: 'absolute',
    top: 0,
    right: 0,
    bottom: 0,
    left: 0,
    alignItems: 'center',
    justifyContent: 'center',
    gap: 12,
    backgroundColor: '#FFF',
  },
  title: { fontSize: 16, fontWeight: '600' },
  desc: { fontSize: 13, color: '#888' },
});

七、缓存隔离与安全 ​

7.1 版本隔离 ​

需求WebView 内 H5 能做必须 Native 兜底

现象原因解法

十、和现有教程怎么衔接 ​

阶段位置能力
05 章现状persist + AsyncStorage设置项持久化，与 H5 无关
09 章统一 kv + op-sqlite + outboxNative 侧离线数据与队列
10 章第一步本地包 + base: './'H5 断网可打开
10 章第二步manifest + 校验 + 回滚H5 可安全升级
10 章第三步JSBridgeH5 复用 09 章的缓存与离线写入
10 章第四步超时 + 兜底页 + 白名单白屏可控、安全边界清晰

具体演进顺序建议：

  1. 先本地化：把 H5 产物打进包，确认双端 file:// 都能加载；
  2. 再接桥：H5 的数据读写改走 cache.get / queue.enqueue，不再直接写 localStorage；
  3. 最后做升级：有稳定本地包之后，再引入 manifest、灰度、签名与回滚；
  4. 不要反过来：先做离线包下载、再做本地加载，会让"包坏了打不开"和"包没下完"两类问题混在一起，极难排查。

FAQ ​

Q1：能不能只用 Service Worker，不做本地包？ iOS 不行。WKWebView 不支持 Service Worker；Android 的 SW 又要求 https/localhost，file:// 包内页面注册不了。SW 只能作为在线 https 页面的补充。

Q2：离线包用 zip 还是单文件 HTML？ 都可以。单文件 HTML（CSS/JS 内联）实现最简单、无需解压，适合小页面；多资源站点用 zip + 解压，但要处理解压失败、磁盘占用与原子切换。本章按 zip 方案给完整流程。

Q3：为什么不在 H5 里直接读写 localStorage？ localStorage 可能被系统清理、容量有限、无事务、无法跨 WebView 实例共享。关键数据必须落 Native 的 op-sqlite/MMKV，H5 只做展示层。

Q4：灰度怎么做才稳？ 用设备 id 的稳定哈希分桶（本章 inRollout），而不是随机数；同时保留"强制回滚开关"，服务端下发 killVersion 后客户端立即切回上一版。

Q5：离线包多大合适？ 首包建议控制在 10MB 以内（首屏 HTML + 关键 CSS/JS + 图标）。大图、视频不要打进离线包，走 Native 图片缓存或按需下载。
