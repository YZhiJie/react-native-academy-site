教程 05 · 状态管理：Zustand + Context 最佳实践 ​

目标：给应用选对状态方案——服务端缓存、全局状态、UI 局部状态各归其位。 版本锚点：zustand@5.0.15。

一、三层状态观（先定原则再写代码） ​

层特征工具
服务端数据会过期、需缓存/去重/重取fetch + 缓存库（SWR/React Query 风格均可）
全局客户端状态多屏共享（登录态、主题、购物车）Zustand
局部 UI 状态只属于一个组件（输入框、开关）useState

反模式警告：把服务端数据塞进全局 store 再手动同步，是 bug 重灾区。全局 store 只放"客户端拥有的事实"。

二、Zustand 入门：一个 store 解决登录态 ​

tsx
// stores/authStore.ts
import { create } from 'zustand';

/**
 * Zustand 5：create<T>()(set, get) 双层调用写法（TS 必须）。
 * 优势：不用 Provider 包根组件，任何文件 import 即用。
 */
type AuthState = {
  token: string | null;
  userId: string | null;
  signIn: (token: string, userId: string) => void;
  signOut: () => void;
};

export const useAuthStore = create<AuthState>()((set, get) => ({
  token: null,
  userId: null,

  // action 1：登录 —— set 局部合并（类似 class setState 浅合并）
  signIn: (token, userId) => set({ token, userId }),

  // action 2：登出 —— 需要读旧值时用 get()，或 set(prev => ...)
  signOut: () => set(prev => ({ ...prev, token: null, userId: null })),
}));

tsx
// 消费端：只订阅需要的字段（性能关键！）
import { useAuthStore } from '../stores/authStore';

function ProfileBadge() {
  // ① 订阅单个字段：token 变化才重渲染，其它字段变化不惊动本组件
  const token = useAuthStore(s => s.token);

  // ② 派生值：useMemo 防止每次渲染生成新引用导致 selector 失效
  const isSignedIn = useMemo(() => token !== null, [token]);

  return <Text>{isSignedIn ? '已登录' : '未登录'}</Text>;
}

// ③ 免订阅取值（事件回调里用，不触发重渲染）
const { token } = useAuthStore.getState();
// ④ 组件外 dispatch（如网络层 401 时自动登出）
useAuthStore.getState().signOut();

性能原理：Zustand 默认用 Object.is 比对 selector 返回值。selector 返回"原始值"是最佳实践；返回新建对象/数组必须包 useShallow（import { useShallow } from 'zustand/react/shallow'），否则每次渲染都误判"变了"。

三、异步 action：请求状态收进 store ​

tsx
// stores/videoStore.ts —— 组件篇聊天/列表都会复用这个模式
import { create } from 'zustand';

type VideoState = {
  videos: Video[];
  status: 'idle' | 'loading' | 'error';
  fetchVideos: () => Promise<void>;
};

export const useVideoStore = create<VideoState>()(set => ({
  videos: [],
  status: 'idle',

  fetchVideos: async () => {
    set({ status: 'loading' });                      // 进入加载态
    try {
      const res = await fetch('https://api.example.com/videos');
      const data = await res.json();
      set({ videos: data, status: 'idle' });         // 成功：一次 set 落库
    } catch (e) {
      set({ status: 'error' });                      // 失败：保留旧数据仅标错误
    }
  },
}));

四、Context 的正确岗位：主题 ​

Zustand 管全局业务，Context 留给"树级注入"场景（主题、依赖注入）：

tsx
// theme/ThemeContext.tsx
import { createContext, useContext, useMemo, useState } from 'react';

const ThemeContext = createContext<'light' | 'dark'>('light');

export function ThemeProvider({ children }: { children: React.ReactNode }) {
  const [theme, setTheme] = useState<'light' | 'dark'>('light');

  // value 必须用 useMemo 包：否则每次渲染新引用，所有消费者全量重渲染
  const value = useMemo(() => theme, [theme]);

  return <ThemeContext.Provider value={value}>{children}</ThemeContext.Provider>;
}

export const useTheme = () => useContext(ThemeContext);

为什么主题不用 Zustand？——可以，两者都行。经验法则：会被深层组件频繁修改、且需要跟着组件树局部作用域走的用 Context（如多主题作用域）；全局单例、跨屏共享的用 Zustand。不要用 Context 存"高频变化"的值（每变一次全树消费者重渲染）。

五、持久化：把 store 落到 AsyncStorage ​

bash
npm i @react-native-async-storage/async-storage
1
tsx
import { create } from 'zustand';
import { persist, createJSONStorage } from 'zustand/middleware';
import AsyncStorage from '@react-native-async-storage/async-storage';

export const useSettingsStore = create<SettingsState>()(
  // persist 中间件：每次 set 自动序列化写入，启动时自动恢复
  persist(
    set => ({
      fontSize: 'medium',
      setFontSize: size => set({ fontSize: size }),
    }),
    {
      name: 'app-settings',                       // 存储 key
      storage: createJSONStorage(() => AsyncStorage), // RN 必须显式指定（默认 localStorage 是 Web 的）
    },
  ),
);

FAQ ​

Q1：Zustand 和 Redux 怎么选？ RN 0.87 + React 19 时代，中小项目 Zustand 的样板代码量远低于 Redux（无 reducer/dispatch），且与并发渲染兼容良好。除非团队已有 Redux 生态沉淀，否则新项目直接 Zustand。

Q2：重渲染风暴怎么排查？ 先检查 selector 是否返回了"新引用"（对象/数组/函数）；再检查 Context value 是否没 memo；最后用 RN DevTools 的 Profiler 看谁在高频渲染。

Q3：store 里能放 WebSocket 连接吗？ 连接句柄放模块级单例，store 只放"连接状态/消息数据"——可序列化、可还原的才是 store 的菜。
