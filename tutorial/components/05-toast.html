组件 05 · Toast 轻提示 ​

react-native-toast-message@2.5.2 —— 非侵入式通知：成功/失败/信息三态、自定义样式、随处可调。 架构预告：它用"命令式 API + 全局挂载点"分离调用方与视图 —— 全 app 只挂一次 <Toast />。

一、安装与配置 ​

bash
npm i react-native-toast-message@2.5.2
1
tsx
// App.tsx —— 挂载点：包在导航容器之后，全 app 只出现一次
import Toast from 'react-native-toast-message';
import { toastConfig } from './config/toastConfig';

export default function App() {
  return (
    <>
      {/* ...导航与其他 UI... */}
      {/* position：默认 top；bottom 则贴底显示 */}
      <Toast config={toastConfig} position="top" topOffset={60} />
    </>
  );
}

二、基础用法：一行调用 ​

tsx
import Toast from 'react-native-toast-message';

// 成功提示（type 对应 config 里的自定义类型，默认 success/error/info）
Toast.show({
  type: 'success',
  text1: '保存成功',
  text2: '你的设置已同步到云端',          // 可选的第二行
  visibilityTime: 2500,                // 展示时长 ms（默认 4000）
  autoHide: true,                      // 自动关闭（false 则手动 hide）
  onPress: () => Toast.hide(),         // 点击提示条关闭
  onShow: () => console.log('出现了'),
  onHide: () => console.log('消失了'),
});

// 失败 / 信息
Toast.show({ type: 'error', text1: '网络异常', text2: '请稍后重试' });
Toast.show({ type: 'info', text1: '提示：向下滚动加载更多' });

import { BaseToast, ErrorToast } from 'react-native-toast-message';

export const toastConfig = {
  // 内置类型覆写：改色改布局
  success: props => (
    <BaseToast
      {...props}
      style=&#123;&#123; borderLeftColor: '#6BCB77', backgroundColor: '#2D2A32' &#125;&#125;
      contentContainerStyle=&#123;&#123; paddingHorizontal: 16 &#125;&#125;
      text1Style=&#123;&#123; color: '#6BCB77', fontSize: 15, fontWeight: '700' &#125;&#125;
      text2Style=&#123;&#123; color: '#EEE', fontSize: 13 &#125;&#125;
    />
  ),
  error: props => (
    <ErrorToast
      {...props}
      style=&#123;&#123; borderLeftColor: '#FF6B9D', backgroundColor: '#2D2A32' &#125;&#125;

  // 完全自定义类型：想叫什么叫什么

四、高级：与服务层联动（全局错误出口） ​

tsx
// utils/request.ts —— 把 Toast 作为全局错误出口（不在每个页面重复 try/catch）
export async function apiGet(url: string) {
  try {
    const res = await fetch(url);
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return await res.json();
  } catch (e) {
    // 网络层统一吐提示，页面只管成功路径
    Toast.show({ type: 'error', text1: '请求失败', text2: String(e?.message ?? e) });
    throw e; // 继续抛出，让业务侧决定是否降级
  }
}

分寸感：Toast 是"非侵入"通知，但滥用即侵入。同一错误在每次重试都弹一次是反模式 —— 关键路径的持续状态用页面内 UI（骨架屏/错误页），Toast 只做"瞬时事件"的回执。

五、自定义技巧 ​

  1. 位置与偏移：position="bottom" + bottomOffset={40}；有底部 Tab 时 topOffset 要加 Tab 高度防遮挡；
  2. 带操作按钮的 Toast：自定义类型里塞 Pressable（如"撤销"），注意 visibilityTime 要延长；
  3. 防重复弹：调用前记录当前 text1 指纹，相同则跳过（或直接 Toast.hide() 后再 show）。

六、性能注意事项 ​

Toast 组件常驻内存但平时不渲染内容（空态开销可忽略）；自定义类型里的动画用 reanimated 驱动（默认 Animated 已够用）；不要在 Toast 里放大图片——它是全局单例，样式膨胀影响所有调用方。

七、常见用例 ​

用例配置
表单校验失败type error + text2 具体原因
操作回执（已复制/已收藏）success + visibilityTime 1500
全局网络错误出口服务层统一调用（见四）
上传进度提示自定义 loading 类型 + autoHide false + 手动 hide

FAQ ​

Q1：Toast 不显示？ 三查：<Toast /> 是否真的挂载（放在导航容器同级或之后）、type 是否在 config 里注册、是否被另一个 show 立刻顶掉。

Q2：能同时显示多条吗？ 不能 —— 单例设计，后一条替换前一条。多条队列需求换 react-native-root-toast 或自建队列包装 Toast.show。

Q3：iOS 上被刘海挡？ topOffset 显式给足（建议 60+），或配合 safe-area-context 的 insets.top 动态计算。
