教程 02 · 项目结构剖析：每个文件都是干什么的 ​

目标：读懂 init 生成的每一个文件，知道"改哪、不动哪"。这直接决定你日后排查问题的速度。

一、目录总览 ​

text
MyApp/
├── App.tsx                  # 你的根组件（业务代码入口）
├── index.js                 # JS 入口：注册根组件（原生侧固定加载它）
├── package.json             # 依赖与脚本
├── metro.config.js          # Metro 打包器配置
├── babel.config.js          # Babel 转译配置（含 worklet 插件位）
├── jest.config.js           # 单测配置
├── tsconfig.json            # TypeScript 配置
├── .prettierrc.js / eslint.config.mjs
├── assets/                  # 图片等静态资源
├── __tests__/               # App 启动冒烟测试
├── android/                 # Android 原生壳工程（Kotlin）
│   ├── app/build.gradle.kts # 应用级配置：SDK 版本、签名、依赖
│   ├── build.gradle.kts     # 工程级配置：插件版本、仓库
│   └── app/src/main/...     # MainActivity.kt / MainApplication.kt / res
└── ios/                     # iOS 原生壳工程（ObjC/Swift）
    ├── Podfile              # CocoaPods 依赖声明
    ├── MyApp.xcodeproj      # Xcode 工程
    └── MyApp/               # AppDelegate.swift / Info.plist / LaunchScreen

二、JS 侧三个关键文件 ​

2.1 index.js —— 原生与 JS 的"接头暗号" ​

js
/**
 * 原生 App 启动后默认加载 bundle 里的 index.js。
 * 它只有一件事：把根组件注册给原生。
 */
import { AppRegistry } from 'react-native';
import App from './App';
import { name as appName } from './app.json';

// name 参数必须与原生侧 app.json/Info.plist 中一致，
// 否则源码里那条经典报错就会出现：
// "MyApp has not been registered"（AppRegistryImpl.runApplication 的 invariant）
AppRegistry.registerComponent(appName, () => App);

三、原生壳工程：什么时候需要动 ​

日常业务 90% 的时间不需要碰 android/ 与 ios/。但以下场景必须进原生层：

场景要改的文件
改应用名/图标/启动图Info.plist、res/strings.xml、AppIcon
声明权限（相机、定位…）Info.plist、AndroidManifest.xml
引入带原生代码的三方库后iOS 需重新 pod install；Android 无需手动
自定义 TurboModule / 原生 View新建 Kotlin/ObjC 文件 + Codegen SPEC
改最低系统版本app/build.gradle.kts 的 minSdk、Xcode 工程设置

3.1 android/app/build.gradle.kts 里值得知道的行 ​

kotlin
android {
    ndkVersion rootProject.ext.ndkVersion      // 0.87 固定的 NDK 版本，勿动
    compileSdk rootProject.ext.compileSdk      // 37（0.87 模板值，源码 libs.versions.toml 锚定）

    defaultConfig {
        applicationId "com.myapp"              // 包名，上架前定死
        minSdkVersion rootProject.ext.minSdkVersion
        targetSdkVersion rootProject.ext.targetSdkVersion
    }
}

四、配置文件速览 ​

文件干什么你常改吗
metro.config.js打包器：模块解析、资源后缀、自定义 transformer引入 svg loader 等才改
babel.config.js语法转译 + 插件（如 reanimated 的 worklet 插件必须排在最后）装动画库时改
tsconfig.jsonTS 严格选项与路径别名建议开 "strict": true
jest.config.js单测环境（内置 RN preset）加测 DOM 时改

五、一次"改起来"的演练 ​

给 App 加个标题，验证热更新链路：

tsx
// App.tsx —— 保存后模拟器应立即刷新
import React from 'react';
import { SafeAreaView, Text, StyleSheet } from 'react-native';

function App(): React.JSX.Element {
  return (
    <SafeAreaView style={styles.container}>
      {/* 与漫画 Part I 联动：这行 Text 最终由 Fabric 挂载上屏 */}
      <Text style={styles.title}>我读懂了项目结构</Text>
    </SafeAreaView>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, justifyContent: 'center', alignItems: 'center' },
  title: { fontSize: 22, fontWeight: '600' },
});

export default App;

FAQ ​

Q1：ios/Pods、android/.gradle 为什么不进 git？ 都是可重建的构建产物（体积巨大），pod install/Gradle 会按 lock 文件还原。锁的是 Gemfile.lock、gradle-wrapper 与 Podfile.lock。

Q2：可以直接删掉 android 或 ios 目录吗？ 不要。0.87 模板已"瘦身"，升级 diff 很小，保留它比"upgrade 助手重建"更稳。

Q3：index.js 能改名吗？ 能，改 package.json 的 "main" 字段，并保持原生侧无硬编码即可；默认没必要。
