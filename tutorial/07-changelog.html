教程 07 · React Native 0.87 更新日志 ​

本章基于官方发布公告（React Native 0.87，2026-08-11）与 0.87.1 官方 npm 源码包交叉核对写成：公告里的每一项，都尽量给出源码中的落点。

一、版本全景 ​

项值
首发版本0.87.0（2026-08-11）
本教程锚点0.87.1（0.87 稳定线上的补丁版本，以 bugfix 为主）
贡献规模265 个提交、74 位贡献者
React peer^19.2.3（源码 package.json peerDependencies）
Node 引擎^22.13.0 || ^24.3.0 || >= 26.0.0
支持窗口变化0.84.x 随 0.87 发布转入 unsupported

怎么读 0.87.0 与 0.87.1 的关系：0.87.0 引入全部特性与破坏性变更；0.87.1 是同一稳定线上的修复版。新项目直接用 0.87.1 即可，特性清单以 0.87.0 公告为准；补丁级的逐项修复见官方 Releases 页。本学院所有源码行号引用均来自 0.87.1 tarball。

二、四大亮点 ​

2.1 Strict TypeScript API 默认启用 ​

0.80 起作为预览的 Strict API，在 0.87 成为默认 JS API：

  • 类型不再手写维护，而是从 RN 源码直接生成（源码包 types_generated/ 目录 + package.json 的 exports["."].types: "./types_generated/index.d.ts" 即为证据），消除了长期存在的"类型与实现漂移"；
  • 公共 API 被严格限定为 react-native 根出口——react-native/Libraries/* 深度导入现在是类型错误；
  • ref 有了专用类型：ViewInstance、TextInputInstance 等；
  • 临时逃生舱：tsconfig 加 "customConditions": ["react-native", "react-native-legacy-deep-imports"] 可回退旧类型，仅保留到 0.88。源码 package.json 的 exports 中可以看到这个 condition 的实际挂载点。

2.2 Metro 0.84 → 0.87：更快、更瘦 ​

  • source map 生成速度 2 倍（RN DevTools 加载明显更快）；
  • source map 存储优化，Metro 内存占用减半；
  • 正式支持 TypeScript / ESM 配置文件（如 metro.config.mts）；
  • 移除 YAML 配置与 .es6 扩展名配置支持；
  • 解析器新特性：package self-resolve（包可引用自己的 exports）。

2.3 iOS 实验性支持 Swift Package Manager（SwiftPM） ​

CocoaPods 近十年的统治地位首次迎来官方替代路径（opt-in，CocoaPods 仍是默认与受支持路径）：

bash
cd ios
npx react-native spm --deintegrate   # 移除 CocoaPods，把 Swift package 引用注入现有 .xcodeproj
1
2
  • 只需 Xcode，不再需要 Ruby / Bundler / CocoaPods；签名、capabilities、build phases 原样保留；
  • 依赖变更后不用再手动跑安装命令，构建时自动重新 autolinking（新 clone / CI 需先跑一次 npx react-native spm）；
  • 社区库若没有 Package.swift，可用 npx react-native spm scaffold 从 podspec 生成；
  • 官方明确标注：命令与生成物布局可能变，暂勿用于生产（RFC #0994）。

配套的头文件破坏性变更：新增 ReactNativeHeaders.xcframework 与 ReactNativeDependenciesHeaders.xcframework，裸角度导入必须补命名空间：

objc
- #import <RCTAppDelegate.h>
+ #import <React/RCTAppDelegate.h>

2.4 Android Gradle Plugin（AGP）9 ​

首个支持 AGP 9 的 RN 版本。源码 gradle/libs.versions.toml 中的实际锚点：agp = "9.2.1"、kotlin = "2.2.0"。

官方当前建议在 android/gradle.properties 关闭 AGP 9 的两个新行为（AGP 10 起这两个开关会被移除）：

properties
# 暂不启用 AGP 9 内置 Kotlin 与新 DSL
android.builtInKotlin=false
android.newDsl=false

3.3 包与工具链 ​

  • @react-native/core-cli-utils 不再发布（仓库内仍保留参考实现）；
  • react-native/rn-get-polyfills 移除 → 用 @react-native/js-polyfills；
  • @react-native/jest-preset 必须作为独立包消费；
  • 不再支持通过 WebSocket 连接独立 react-devtools 包 → 统一用 React Native DevTools（教程 06 章）。

六、0.87.1 补丁版说明 ​

0.87.1 不引入新特性，遵循 semver 补丁约定：修复 0.87.0 后的稳定性问题。本教程组件篇给出的三方库版本组合（如 Reanimated 4.7.0 + react-native-worklets 0.13.0，旧版 Reanimated 3.19.5 与 0.87 工具链编译不兼容）均已在 0.87.1 上验证。具体补丁条目以官方 GitHub Releases 为准。

FAQ ​

Q1：0.84 项目还能收到安全修复吗？ 不能。0.87 发布后 0.84.x 转入 unsupported。建议至少升到 0.86（无用户侧破坏性变更的过渡版本）再冲 0.87。

Q2：Strict API 只影响类型，运行时不受影响吧？ 对。它是纯 TypeScript 分析层变化，按 tsconfig 作用域生效，App 与三方库可以独立迁移，不影响线上 bundle。

Q3：必须现在就切 SwiftPM 吗？ 完全不用。SwiftPM 是实验特性，CocoaPods 是默认且受支持路径，生产项目继续用 Podfile。
