教程 01 · 环境搭建与项目初始化 ​

目标：在本机装好 RN 0.87.1 的全部依赖，用官方 CLI 创建第一个能跑的项目，并理解"每一步装了什么"。 前置知识：会用终端，了解 npm/pnpm 基本命令。

一、版本要求（0.87.1 特有，必须先看） ​

React Native 0.87.1 的 package.json engines 明确要求：

依赖版本说明
Node.js^22.13.0 || ^24.3.0 || >= 26.0.018/20 已不被支持，装错版本 Metro 会直接报错
React19.2.3（peer 自动带入）新架构配套的 React 版本
Metro0.87.x（RN 内置）打包器，不用单独装
RN CLI20.2.0脚手架与构建命令
项目模板@react-native-community/template 0.87.2生成项目里 package.json 的版本

用 nvm 锁版本：

bash
# 安装并切换到满足要求的 LTS 版本（22 或 24 均可）
nvm install 22.13.0
nvm use 22.13.0

# 校验：必须 ≥ 22.13
node -v

为什么卡这么死？0.87 的 Metro 与 Codegen 用了 Node 22 的新 API（如稳定排序、更快的 fs.glob），低版本 Node 会在构建期报 is not a function 这类难排查的错误。起步先对齐版本，能省两小时。

2.3 Windows（Android 方向） ​

  1. 安装 Android Studio，勾选同样的 SDK 组件；
  2. 系统环境变量里配置 ANDROID_HOME，并把 platform-tools 加入 Path；
  3. 安装 JDK 17 并配置 JAVA_HOME（官方要求 17，勿用更高版本）；
  4. 可选安装 React Native Community CLI Doctor 检测（下一步会用到 doctor）。

三、创建项目 ​

bash
# 用 CLI 20.2.0 创建项目，并锁定 RN 版本为 0.87.1
npx @react-native-community/cli@latest init MyApp --version 0.87.1

cd MyApp

命令解读：

  • @react-native-community/cli@latest：显式指定 CLI 大版本（20.x），避免旧全局 CLI 干扰；
  • --version 0.87.1：决定生成项目 package.json 里 react-native 的版本与模板版本（0.87.2）；
  • 生成的项目默认新架构（bridgeless + Fabric + Hermes），无需再开任何开关。

4.3 双端通用：Metro ​

bash
npm start              # 启动 Metro 0.87 开发服务器（默认 8081）
1

看到 Loading dependency graph, done. 后，模拟器里出现 "Welcome to React Native" 即成功。修改 App.tsx 保存，模拟器自动热更新。

常见坑：

  • pod install 卡在 CDN 下载：国内网络先 export COCOAPODS_CDN_URL 或使用镜像；
  • Android 首次构建极慢：Gradle 会下载 NDK/CMake 与依赖，属正常现象，第二次起增量构建秒级；
  • 8081 端口被占：lsof -i :8081 找到进程杀掉，或 Metro 用 --port 换端口。

五、自检清单（doctor） ​

bash
npx @react-native-community/cli doctor
1

输出应全绿：Node 版本、JDK、Android SDK、Xcode 各项通过。任何一项 ❌ 都按提示修复后再继续，环境不干净是后面所有教程报错的头号来源。

FAQ ​

Q1：能用 Expo 吗？ 本教程使用 RN CLI 裸项目（可自由改原生代码）。Expo 也能跑 0.87，但组件篇里需要改原生配置的库（Blur、Pager View 等），裸项目路径更直接。

Q2：pnpm 可以吗？ 可以，但 RN 0.87 的 pod 自动链接对 pnpm 的符号链接结构敏感，需在 .npmrc 配 node-linker=hoisted。新手建议先用 npm，少一层变量。

Q3：--version 0.87.1 报"找不到版本"？ 检查 Node 版本是否达标（≥22.13）与网络是否可达 npm registry；公司内网需配置代理。
