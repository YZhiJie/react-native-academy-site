教程 16 · 覆盖规划与原生桥接：往复式、BFS/A*、Kotlin TurboModule 与弱网验收 ​

目标：把地块变成一条可执行的割草路径，用 Android 原生模块补齐串口能力，并用可复现的故障矩阵证明"弱网可用"。 版本锚点：React Native 0.87.1 + React 19.2.3 + TypeScript 严格模式；Android 侧 Kotlin + New Architecture codegen。 前置：14 · 通信底座、15 · 地图与轨迹、漫画 04 · TurboModules 与 Codegen。

前两章解决了"连得上"和"看得见"。这一章解决最后一段：机器怎么走，以及凭什么说它在弱网下能用。

一、往复式覆盖：规则先行 ​

割草行业最常用的基础路径是 boustrophedon（牛耕式）：一行从左到右，下一行从右到左，像牛拉犁来回走。

它不追求"数学最优"，追求可解释、转弯少、覆盖率稳定。四步：

  1. 把地块旋转到"割幅方向"为 x 轴，让扫描线变成水平线；
  2. 按 spacing 从下到上取扫描线，与多边形求交；
  3. 交点排序后两两配对（奇偶规则），得到"在院内"的线段；
  4. 相邻扫描线交替方向，行尾插入转弯点，最后旋转回原坐标系。
ts
// 原型：mower-console-demo/src/core/plan/boustrophedon.ts
/** 用直线 y = cutY 与多边形求交，返回排序后的 x 交点 */
function scanlineIntersections(points: ReadonlyArray<Point>, cutY: number): number[] {
  const xs: number[] = [];
  for (let i = 0; i < points.length; i += 1) {
    const a = points[i];
    const b = points[(i + 1) % points.length];
    if ((a.y > cutY) === (b.y > cutY)) continue; // 不相交或水平边
    const t = (cutY - a.y) / (b.y - a.y);
    xs.push(a.x + t * (b.x - a.x));
  }
  xs.sort((left, right) => left - right);
  return xs;
}

/** 对扫描线交点做奇偶配对，得到多边形内部的线段 */
function pairIntervals(xs: number[]): Array<[number, number]> {
  const intervals: Array<[number, number]> = [];
  // 凹多边形同一行会有 4 个、6 个交点，必须 0-1、2-3 成对，
  // 不能简单取 min/max，否则会把"院子外的缺口"也连进去
  for (let i = 0; i + 1 < xs.length; i += 2) {
    if (xs[i + 1] - xs[i] > 1e-6) intervals.push([xs[i], xs[i + 1]]);
  }
  return intervals;
}

二、障碍物避让：裁剪 + 栅格 + A* ​

有了基础割草线，还要处理树、花坛、水池。原型分两层：

  1. 裁剪：把障碍物换算成路径参数区间，直接从割草线上减掉；
  2. 连接：被障碍打断的两段之间，直线可达就直接连，不可达就 BFS/A* 绕行。

2.1 裁剪：一次差集，不要逐点判断 ​

ts
// 原型：mower-console-demo/src/core/plan/coverage.ts
for (const swath of base.swaths) {
  // 圆形与矩形障碍统一换算成路径参数区间，一次做差集
  const pieces = clipSegmentByObstacles(swath.from, swath.to, obstacles, inflation);
  const usable = pieces.filter(([a, b]) => distance(a, b) >= 0.15);
  if (usable.length === 0 && distance(swath.from, swath.to) > 0.15) {
    clippedSegments += 1;
    continue;
  }
  const ordered = swath.forward ? usable : [...usable].reverse();
  for (const [a, b] of ordered) {
    const from = swath.forward ? a : b;
    const to = swath.forward ? b : a;
    segments.push({ from, to, row: swath.row, forward: swath.forward });
  }
}

2.2 栅格：A* 的搜索空间 ​

ts
// 原型：mower-console-demo/src/core/plan/grid.ts
constructor(
  readonly bounds: Bounds,
  readonly cellSize: number,
  private readonly polygon: ReadonlyArray<Point>,
  private readonly obstacles: ReadonlyArray<Obstacle>,
  /** 机器半径 + 安全距离；障碍物按它膨胀 */
  readonly inflation: number,
) {
  this.cols = Math.max(1, Math.ceil((bounds.maxX - bounds.minX) / cellSize) + 1);
  this.rows = Math.max(1, Math.ceil((bounds.maxY - bounds.minY) / cellSize) + 1);
  this.blocked = new Uint8Array(this.cols * this.rows);

  for (let row = 0; row < this.rows; row += 1) {
    for (let col = 0; col < this.cols; col += 1) {
      const point = this.toPoint(col, row);
      this.blocked[row * this.cols + col] = pointBlocked(polygon, obstacles, point, inflation)
        ? 1
        : 0;
    }
  }
}

2.3 A*：八方向 + octile 启发 + 二叉堆 ​

ts
// 原型：mower-console-demo/src/core/plan/grid.ts
const heuristic = (col: number, row: number): number => {
  const dx = Math.abs(col - goalCell.col);
  const dy = Math.abs(row - goalCell.row);
  // 八方向移动的 octile 距离：直线 1，斜线 √2
  return (dx + dy) + (Math.SQRT2 - 2) * Math.min(dx, dy);
};

while (open.size > 0) {
  const current = open.pop() as number;
  if (closed[current]) continue;
  closed[current] = 1;
  visited += 1;
  if (current === goalIndex) break;

  const col = current % grid.cols;
  const row = Math.floor(current / grid.cols);
  for (const neighbor of NEIGHBORS) {
    const nc = col + neighbor.dx;
    const nr = row + neighbor.dy;
    if (grid.isBlocked(nc, nr)) continue;
    // 禁止斜穿墙角：对角线移动要求两个正交邻格都可走
    if (neighbor.dx !== 0 && neighbor.dy !== 0) {
      if (grid.isBlocked(col + neighbor.dx, row) || grid.isBlocked(col, row + neighbor.dy)) {
        continue;
      }
    }
    const tentative = gScore[current] + neighbor.cost;
    if (tentative < gScore[neighborIndex]) {
      gScore[neighborIndex] = tentative;
      cameFrom[neighborIndex] = current;
      open.push(neighborIndex, tentative + heuristic(nc, nr));
    }
  }
}

三个容易漏的点：

  1. open 集必须是堆。数组每次 sort 会退化成 O(n²)，2 万格时肉眼可见地卡。
  2. 斜向不能穿墙角。两个正交邻格有一个被挡，就不允许斜着过去，否则路径会"擦着"障碍物膨胀区的尖角。
  3. 终点可能落在膨胀区。用 nearestFree 向外找最近空闲格，并把 path[0] 一起带上，否则连接段可能擦过障碍物。

2.4 为什么还要 BFS ​

A* 回答"怎么走最短"，BFS 回答"能不能到"。听起来 BFS 多余，但：

  • 被障碍完全隔断时，A* 会展开整个连通域才失败，代价高；
  • 覆盖率规划里，先 BFS 判断两段割草线是否连通，不连通就直接跳过并记录 disconnected，比 A* 便宜；
  • BFS 只做四邻域，实现简单、结果稳定，适合做前置判定。

kotlin
// 原型：mower-console-demo/android/app/src/main/java/com/mowerconsole/serialprobe/NativeSerialProbeModule.kt
class NativeSerialProbeModule(reactContext: ReactApplicationContext) :
  NativeSerialProbeSpec(reactContext) {

  override fun getName(): String = NAME

  override fun isSupported(): Boolean {
    return reactApplicationContext.packageManager
      .hasSystemFeature(PackageManager.FEATURE_USB_HOST)
  }

  override fun listUsbDevices(promise: Promise) {
    try {
      val manager = reactApplicationContext
        .getSystemService(Context.USB_SERVICE) as? UsbManager
        ?: run {
          promise.resolve("[]")
          return
        }
      val array = JSONArray()
      for (device in manager.deviceList.values) {
        var hasSerial = false
        for (index in 0 until device.interfaceCount) {
          val intf = device.getInterface(index)
          val isCdc = intf.interfaceClass == UsbConstants.USB_CLASS_COMM
          val isVendor = intf.interfaceClass == UsbConstants.USB_CLASS_VENDOR_SPEC
          if (isCdc || isVendor) hasSerial = true
        }
        array.put(JSONObject().apply {
          put("deviceId", device.deviceId)
          put("vendorId", device.vendorId)
          put("productId", device.productId)
          put("name", device.deviceName)
          put("hasSerialInterface", hasSerial)
        })
      }
      promise.resolve(array.toString())
    } catch (error: Exception) {
      promise.reject("USB_ENUM_FAILED", error)
    }
  }

  companion object {
    const val NAME = "NativeSerialProbe"
  }
}

3.3 为什么只做"枚举"不做"读写" ​

这是本章最重要的边界说明：

  • 枚举 USB 设备不需要申请权限，可以直接展示连接状态；
  • 真正的 CDC-ACM 读写要 requestPermission（系统弹窗）→ claimInterface → bulkTransfer，每一步都必须真机验证；
  • 本机 Android 模拟器因 HVF error: HV_DENIED 无法启动，运行时验证做不了。

所以原型的结论停在：codegen 跑通、Kotlin 编译通过、assembleDebug 成功、iOS 侧可优雅降级。
不做的结论：USB 串口真实读写、CH340/CP2102/FTDI 兼容性、热插拔重连。这些全部标记为未验证，不用"代码写了"冒充"功能可用"。

4.1 最关键的坑：丢包单位是 MQTT 报文，不是 WebSocket 帧 ​

第一版代理按 WS 帧丢包，结果测出来的不是"丢包重传"，而是"协议流被撕碎"：

  • aedes 通过 ws stream 发送时，会把一个 MQTT 报文拆成多个 WS 帧；
  • 一个 CONNACK 可能被拆成 4 个单字节帧；
  • 丢掉其中一帧，客户端解码直接错位，连接根本建不起来。

真实网络的丢包单位是 IP 包，TCP 会重传，应用层永远看到完整字节流。所以在应用层模拟丢包，必须以完整 MQTT 报文为单位：

几个值得解释的数字：

  • 丢包场景 ACK 反而快（18ms）：因为 QoS1 在传输层重传，业务 ACK 只要有一条成功就记一次；平均延迟被快速成功的那些拉低了。看平均值会骗人，必须同时看 publishAttempts（21 次）和最大断流。
  • 断网恢复 4651ms > 断网 4000ms：多出来的 651ms 是重连握手 + 退避等待 + 重放。这个差值才是"恢复开销"。
  • 遥测断流 4932ms > 恢复 4651ms：遥测是 2Hz，恢复后要等下一帧才能观测到，所以断流窗口天然比连接恢复多几百毫秒。

五、关键点 ​

  1. 往复式是"规则 + 几何"，不是搜索。先把扫描线、奇偶配对、交替方向做对，再谈优化。
  2. 参数比算法更影响结果：spacing、margin、heading 取错，A* 再好也救不回来。
  3. 裁剪和栅格必须共用同一个 inflation，否则路径会"看起来避障、实际擦边"。
  4. A 的 open 集用堆*，斜向禁止穿墙角，终点落在障碍区要 nearestFree。
  5. BFS 做可达性前置判定，比 A* 失败后才发现更便宜。
  6. 规划结果要带诊断字段（astarCalls、astarVisited、disconnected），否则无法解释"为什么这条路这么怪"。
  7. TurboModule 的 spec 是契约，codegen 生成抽象类；手写模块必须显式注册。
  8. 弱网结论必须带场景、口径、环境。"平均 ACK 18ms"单独看没有意义。

六、常见坑 ​

  1. 按 WebSocket 帧丢包：一个 MQTT 报文被拆成多帧，丢一帧就把协议流撕碎，测出来的是解码错误而不是重传。
  2. A 斜穿墙角*：只判断目标格可走，不判断两个正交邻格，路径会从障碍物膨胀区的尖角擦过去。
  3. inflation 两处不一致：裁剪用 0.3m，栅格用 0.18m，视觉上避开了，实际刀盘会碰到。
  4. 覆盖率公式当成实际覆盖：割草线长度 × 行距 / 面积 是理论上限，不含转弯、边界、障碍物；88% 不代表漏割 12%。
  5. A 失败后静默跳过*：UI 显示一条完整路径，实际有区域没走到。必须把 disconnected 暴露给用户。
  6. 把 assembleDebug 通过写成"Android 已验证"：构建通过只证明编译和链接，不证明运行时、权限、USB 枚举可用。
  7. 在大图上每帧重规划：15 万格的建图 + A* 放在 JS 主线程会卡；应该节流、增量规划或下沉原生。
  8. 只测平均延迟：丢包场景平均值会被快速成功的请求拉低，必须同时看重试次数和最大断流。
